01법인카드 지출 자동입력

문제
카드 사용자가 매달 지출 건마다 계정과목 · 사용 내역 · 함께 사용한 인원(경비인원)을 일일이 입력해야 했습니다.
설계
같은 사용자가 같은 가맹점에서 쓴 과거 내역 중 금액과 사용 시각이 가장 가까운 건을 찾아 입력 후보로 제시하고, 사용자가 확정하기 전까지는 원본 데이터에 반영하지 않도록 했습니다. 이미 입력된 값은 덮어쓰지 않으며, 사용자가 후보와 다르게 수정하면 '자동' 표시를 해제해 누가 입력했는지 추적할 수 있게 했습니다.
결과
사용자는 후보를 확인하고 필요한 부분만 고치면 됩니다. 테스트 중에는 빈 값끼리 비교되지 않아 '자동' 표시가 해제되지 않던 예외를 찾아 수정했습니다.
기여 범위
두 단계 구조는 요구사항으로 받았고, 적용 대상과 예외 조건을 정의해 구현했습니다. ↳ 플로우차트 | 법인카드 자동입력 플로우

문제
문제 은행의 문항이 부족하면 출제가 중간에 실패했고, 운영자는 어떤 문항이 부족한지 알 수 없었습니다.
설계
출제 전에 과목 · 난이도별로 필요한 문항 수와 보유 문항 수를 비교해, 부족하면 어느 과목 · 난이도에서 몇 문항이 모자란지 안내하도록 했습니다. 또 출제를 전부 막는 대신 가능한 과목부터 만드는 부분 출제를 제안해 반영했습니다.
결과
운영자는 보충할 문항을 바로 파악할 수 있고, 시험 일정을 미루지 않아도 됩니다. ↳ 예시화면 | 문제 부족 안내 · 플로우차트 | 출제 전 검증 플로우

02난이도 비율 배분과 합계 보정

문제
난이도 비율(예: 상 30% · 중 50% · 하 20%)대로 문항 수를 나누면 반올림 때문에 합계가 설정값과 달라질 수 있었습니다.
설계
합계가 모자라면 비율이 가장 높은 난이도에 1문항을 더하고, 넘치면 비율이 가장 낮은 난이도에서 1문항을 빼도록 보정 규칙을 정했습니다. 검증 단계와 실제 출제 단계에 같은 규칙을 적용했습니다.
결과
시험지의 문항 수가 항상 설정한 문항 수와 일치합니다.

Databricks Genie API 기반 데이터 조회 챗봇 PoC

제조 고객사의 사내 데이터 조회 및 시각화를 위한 챗봇 PoC입니다. Databricks Genie를 활용해 자연어 기반 데이터 조회 기능을 구현하고, 표 형태로 반환되는 API 응답을 분석해 차트 생성 여부와 유형을 결정하는 로직을 설계했습니다.

  • 화면 설계
  • API 연동
  • 상태 관리
  • 결과 렌더링
상황
사내 데이터 조회 챗봇의 구현 가능성을 빠르게 검증하기 위해 Databricks Genie를 활용했습니다. 다만 Genie API는 조회 결과를 표 형태로만 반환하므로, 사용자가 데이터의 추이를 직관적으로 파악할 수 있도록 별도의 차트 생성 기능이 필요했습니다.
구현 방식
Genie API의 응답 데이터를 기반으로 차트 생성 여부와 유형을 결정하는 로직을 설계했습니다. 질의 내용과 조회 결과의 특성을 고려해 시각화가 적절한 경우에만 차트를 생성하도록 구성했습니다.

01응답 결과 시각화 판단

문제
Genie API는 질의 결과를 원본 데이터로만 돌려주고, 차트는 제공하지 않았습니다.
설계
질문에 담긴 추이 · 비교 · 분포 키워드와 응답 데이터의 수치형 컬럼 비율 · 행 수 · 카테고리 여부에 가중치를 매겨 표시 방식을 나누도록 했습니다.
결과
차트로 보기 적합한 결과는 차트와 그리드를 함께, 그렇지 않으면 그리드만 보여 줍니다. 차트는 5종 중에서 자동으로 고릅니다. ↳ 플로우차트 | 결과 시각화 플로우

설계
사용자별 Databricks 계정으로 인증한 뒤, 접근 가능한 Unity Catalog 목록에서 골라 들어가도록 했습니다.

삼국지로 배우는 데이터 분석

적벽대전의 기록을 직접 세고 숫자로 풀어 보며 데이터 분석의 순서를 익히는 학습 웹앱입니다.

문제
데이터 분석 입문자는 용어와 수식에서 막히고, 게임 능력치는 근거를 알 수 없습니다.
컨셉
“만약 그때, 다른 일이 있었다면?”

기획 포인트

  • 왜 적벽대전인가: 많은 사람이 알고, 인물·전투·계책이 기록으로 남아 직접 세어 볼 수 있는 이야기입니다(『삼국지연의』 제43~50회).
  • 인물과 배·불·계책 글자를 직접 세어 숫자로 바꾸고, 숫자가 나온 원문을 바로 확인하며 숫자가 곧 능력은 아니라는 한계도 스스로 찾습니다.
  • 질문 하나를 6단계로 풀며 분석 개념을 익힙니다. 각 단계는 사례 → 해 보기 → 결과 → 이름 순이라 용어가 먼저 나오지 않습니다.
    1. 명단 정하기
    2. 평균의 함정
    3. 지표 만들기
    4. 민감도 확인
    5. 근거 확인
    6. 가정 실험
  • 가정 실험: 제갈량을 조조 편으로 옮기면 지수가 83에서 72로, 바람도 따라간다고 두면 52(비슷함)가 됩니다. 분석이 정답 찾기가 아니라 근거로 비교하는 일임을 경험합니다.
